# ada 使用说明 —— 启动与挂载 WorkBuddy

## 一、前置条件

| 依赖 | 检查 | 说明 |
|---|---|---|
| adb | `adb devices` 能列出设备 | 已装在 ~/Library/Android/sdk/platform-tools |
| 真机 | 开 USB 调试 + 插线 + 手机上确认授权弹窗 | 状态应为 `device` 而非 `unauthorized` |
| Ollama（可选） | `bash ~/AI/scripts/ollama_start.sh` | 只有探索模式和 LLM 深度诊断需要；**不要用 brew services 启动**（会丢模型路径配置） |
| Python | 系统 python3（3.13）即可 | 依赖：PyYAML + mcp（已装） |

## 二、三种使用方式

### 1. WorkBuddy 对话（已挂载 ✅）

MCP 配置已写入 `~/.workbuddy/mcp.json`（服务名 `ada`）。

**首次启用**：打开 WorkBuddy → 连接器管理页面 → 右上角「自定义连接器」入口 → 找到 `ada` → 点「信任」。之后新对话里直接说人话即可，例如：

- 「看看手机连着没」→ 自动调 `ada_devices`
- 「装一下这个 APK 到 POS 上」→ `ada_install`
- 「跑一下 battery_drain 用例，崩了告诉我原因」→ `ada_run_scenario`（自动诊断+出报告）
- 「采 10 秒日志看看有没有崩溃」→ `ada_logcat`

> 安全设定：MCP 模式下破坏性操作（卸载/清数据/重启）一律拒绝——要执行请走 CLI（会有人工确认）。

### 2. 命令行（功能最全）

```bash
cd ~/workspace/android-debug-agent
export PYTHONPATH=src

python3 -m ada.cli devices                                   # 列设备
python3 -m ada.cli --workdir ./ada_out run examples/battery_drain.yaml -s ND3TNP00003 -p <包名>
python3 -m ada.cli explore "测试登录流程" -s ND3TNP00003 -p <包名>   # 需 Ollama
python3 -m ada.cli verify <用例> --fingerprint <指纹> --apk <修复版.apk> -s ND3TNP00003
python3 -m ada.cli regress -s ND3TNP00003                    # 回归库全量
python3 -m ada.cli crashes history                           # 崩溃指纹库
python3 -m ada.cli mrun <用例> -s 设备1,设备2                 # 多设备对照
```

### 3. 定时巡检（可选）

可以把 `ada regress` 挂成每日自动化（WorkBuddy 自动化功能），每天早上对插着的设备全量回归，发现回归崩溃自动告警。

## 三、产物位置（ada_out/）

| 文件 | 内容 |
|---|---|
| `report_<用例>.md` | Markdown 诊断报告 |
| `replay_<用例>.html` | HTML 逐步回放报告（双击即可看） |
| `crashdb.sqlite` | 崩溃指纹库（`ada crashes history` 查看） |
| `regression_cases/` | 沉淀的回归用例 |
| `perf.sqlite` | 性能基线 |
| `rules.json` | 学习到的诊断规则 |
| `audit.jsonl` / `privacy_audit.jsonl` | 操作审计 / 数据外发审计 |

## 四、常见问题

- **Ollama 报模型为空/连不上**：`bash ~/AI/scripts/ollama_start.sh`（脚本已修好模型路径）；别用 brew services。
- **MCP 里看不到 ada 工具**：连接器管理页确认已点「信任」；配置改动后需新开对话。
- **设备 unauthorized**：拔掉重插，手机上勾选「一律允许这台电脑」。
- **跑用例时 POS 自带收银应用抢前台**：已内置前台守护，正常现象，报告时间轴里会有「前台守护」标记。
